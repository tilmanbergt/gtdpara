# Closing out a project

When a project is finished, gtdpara helps you end it cleanly: nothing left open, results where they belong, and a complete record in the Archive. This is the **close-out**.

## Where to start it

- On the project's **Current** tab, tap **Close out…** in the status section.
- In the Weekly Review, the step **Done awaiting review** lists all projects marked Done. Each has **Close out…** and **Quick archive…**.

You can leave the close-out at any time. Every decision is saved in the project's file (in a `## Close-out` section), so next time it continues where you stopped.

## The five steps

1. **Checklist**: shows the project's area, when it was done and where it will go in the Archive. It lists what still needs attention. Open todos and future meetings block archiving; handle them right there: a todo with Done, Cancel, → Area or → Inbox, a meeting with Cancel, → Area or → Inbox. A moved item takes its own note along (gtdpara asks first); a page in a shared note stays where it is and stays linked. A folder of the same name already in the Archive also blocks; rename one of them by hand. Meetings that were not closed out, goals that still point to the project, links from other folders into it, and open lasso marks are shown as warnings. **Process ›** next to a mark opens it for processing; marks left at archiving move to the Inbox (see [Lasso](lasso.md)). **Change…** next to the area assigns another area, or none. **Edit** next to "Done on" changes the done date, which decides the archive year.
2. **Contents**: every file of the project, grouped the way the PDF will be. Notes and images are included by default. PDFs stay separate files and are only listed; other file types can't be included. Tick or untick what goes in.
3. **Outcomes**: which files live on after the project, for example a finished document. Choose a folder in the area or in Resources for each, or leave it in the archive. Nothing moves yet.
4. **PDF**: **Create PDF** turns all included notes into one PDF with a table of contents that links to each part. **Open PDF to check** opens it in the Supernote's reader. Confirm with **I checked the PDF - it looks right**. If you change contents or outcomes later, you have to check the PDF again. **Create again** first asks whether to replace the existing PDF; nothing is written until you tap **Replace**. While it is being made, the PDF and its page images stay in gtdpara's own private folder; only the finished PDF appears in the project folder.
5. **Archive**: shows exactly what will happen, step by step. **Archive now** moves the outcomes, the PDF, any open marks (to the Inbox) and the project folder. If something fails, nothing is undone; fix the cause and tap **Archive now** again to continue.

## Where things end up

The Archive is sorted by the year the project was done:

- `4 Archive/<year>/<area>/<project>/`: the project folder
- `4 Archive/<year>/<area>/<project>.pdf`: its PDF, right next to the folder

A project without an area goes directly into `4 Archive/<year>/`. The PDF is meant as the long-term record: you can copy it off the Supernote and read it on any device.

## Quick archive

**Quick archive…** (in the Review's Done step) runs only the checklist and then archives - no PDF and no moving of outcomes. Use it for small projects that don't need a record.

## Areas

Areas have no close-out. **Archive…** on an area's Current tab (or **Archive** in the Review) first shows where the folder goes, then moves it to `4 Archive/<year>/`. Open lasso marks of the area move to the Inbox first. An area that still has active or on-hold projects can't be archived.

If that area folder already exists in the Archive (for example because done projects of the area were archived before), the area's contents are added to it. The area's old folder is then empty; the confirmation names it and says it will be deleted, and the Supernote asks you once to allow deleting. If you say no, the empty folder simply stays and gtdpara tells you so.
